# Ayla First Playable Milestone

## 목적

이 문서는 Ayla의 첫 playable version을 구현하기 전에 구현 순서, 단계별 완료 기준, 후속 이슈 분해 기준을 정리한다.

첫 playable의 범위는 `2026-05-06-ayla-first-playable-scope.md`를 기준으로 한다. 이번 문서는 Unity 구현 자체가 아니라, 이후 구현 작업을 작은 단위로 나누기 위한 계획 기준이다.

## 구현 순서 기준

첫 playable 구현은 기반 시스템을 순서대로 쌓는 방식으로 진행한다.

구현 순서는 다음과 같다.

1. 작업실 이동과 고정 쿼터뷰 카메라
2. 기본 상호작용과 한 번에 하나 들기 규칙
3. 포션 제작 도구 기본 흐름
4. 카운터 손님 주문과 전달 흐름
5. 하루 제한 시간과 판매 정산
6. 첫 playable 설비 업그레이드
7. 첫 playable 통합 점검과 임시 캐릭터 모델 적용

초기 구현은 캡슐 캐릭터와 그레이박스 작업실로 시작한다. 외부 모델 수급이나 최종 아트 방향이 정해지지 않아도 이동, 카메라, 상호작용, 제작 흐름 검증을 먼저 진행하기 위함이다.

다만 첫 playable 완료 범위에는 임시 캐릭터 3D 모델 적용과 이동감 재확인이 포함된다. 캡슐 캐릭터만으로는 실제 캐릭터의 크기감, 회전감, 고정 쿼터뷰에서의 실루엣 가독성을 충분히 판단하기 어렵기 때문이다.

최종 캐릭터 아트, 최종 작업실 아트, 최종 애니메이션 품질은 첫 playable 범위에서 제외한다.

## 후속 이슈 구조

첫 playable 구현은 하나의 부모 이슈 아래 여러 구현 서브이슈로 나눈다.

부모 이슈는 첫 playable 전체 진행 상황을 추적하기 위한 이슈다. 각 서브이슈는 Unity에서 직접 구현하고 검증할 수 있는 작업 단위다.

권장 이슈 구조는 다음과 같다.

```text
[Feat] 첫 playable 구현
├─ [Feat] 작업실 이동과 고정 쿼터뷰 카메라 기본 구현
├─ [Feat] 기본 상호작용과 한 번에 하나 들기 규칙 구현
├─ [Feat] 포션 제작 도구 기본 흐름 구현
├─ [Feat] 카운터 손님 주문과 전달 흐름 구현
├─ [Feat] 하루 제한 시간과 판매 정산 구현
├─ [Feat] 첫 playable 설비 업그레이드 구현
└─ [Feat] 첫 playable 통합 점검과 임시 캐릭터 모델 적용
```

부모 이슈는 구현의 큰 방향과 전체 완료 정의를 담고, PR은 가능한 한 서브이슈 단위로 연결한다. 서브이슈 하나는 Unity에서 직접 실행해 확인할 수 있는 목표와 완료 기준을 가져야 한다.

## 1. 작업실 이동과 고정 쿼터뷰 카메라

### 목표

플레이어가 작은 작업실 안에서 에일라를 직접 움직이고, 고정 쿼터뷰 카메라로 작업실 전체 동선을 읽을 수 있게 한다.

이 단계에서는 캡슐 캐릭터와 그레이박스 작업실을 사용한다.

### 완료 기준

- 캡슐 캐릭터를 키보드 또는 패드 입력으로 이동할 수 있다.
- 캐릭터가 작업실 바닥 안에서 이동하고, 벽이나 큰 설비 위치를 기준으로 공간감을 확인할 수 있다.
- 고정 쿼터뷰 카메라에서 캐릭터, 카운터, 주요 설비 후보 위치가 한눈에 읽힌다.
- 카메라 조작, 3인칭 추적 카메라, 자유 카메라는 포함하지 않는다.

### 후속 이슈 후보

- `[Feat] 작업실 이동과 고정 쿼터뷰 카메라 기본 구현`

## 2. 기본 상호작용과 한 번에 하나 들기 규칙

### 목표

플레이어가 가까운 설비나 카운터와 상호작용하고, 한 번에 하나의 대상만 들고 이동하는 핵심 규칙을 만든다.

이 단계는 이동과 카메라에서 분리한다. 한 번에 하나만 들 수 있다는 제한이 첫 playable의 제조 리듬과 동선 판단을 만드는 핵심 규칙이기 때문이다.

### 완료 기준

- 가까운 상호작용 대상이 감지된다.
- 상호작용 입력으로 대상의 기본 동작을 실행할 수 있다.
- 플레이어의 현재 소지 상태가 구분된다.
- 플레이어는 한 번에 하나의 재료, 준비된 재료, 또는 완성 포션만 들 수 있다.
- 이미 무언가를 들고 있을 때 다른 대상을 추가로 들 수 없다.

### 후속 이슈 후보

- `[Feat] 기본 상호작용과 한 번에 하나 들기 규칙 구현`

## 3. 포션 제작 도구 기본 흐름

### 목표

재료 선반, 절구/손질대, 솥, 병입대를 오가며 포션을 만드는 기본 흐름을 구현한다.

개별 재료 물리 오브젝트를 배치하고 집는 시스템은 만들지 않는다. 핵심은 설비를 오가는 순서와 손작업 리듬이다.

### 완료 기준

- 재료 선반에서 재료를 선택하거나 가져올 수 있다.
- 절구/손질대에서 재료를 준비 상태로 바꿀 수 있다.
- 솥에서 준비된 재료를 포션 상태로 진행시킬 수 있다.
- 병입대에서 완성 포션을 만들 수 있다.
- 기본 흐름은 다음 순서를 따른다.

```text
재료 선반 -> 절구/손질대 -> 솥 -> 병입대
```

### 후속 이슈 후보

- `[Feat] 포션 제작 도구 기본 흐름 구현`

## 4. 카운터 손님 주문과 전달 흐름

### 목표

손님이 카운터 바깥에 도착하면 주문이 자동 등록되고, 플레이어가 완성 포션을 카운터에 전달할 수 있게 한다.

### 완료 기준

- 손님 1명이 카운터 바깥에 도착한다.
- 손님 도착 시 주문이 자동으로 등록된다.
- 주문 정보가 월드 말풍선 또는 주문 메모 UI로 표시된다.
- 플레이어가 완성 포션을 카운터에 전달할 수 있다.
- 전달된 포션이 주문과 맞는지 성공 또는 실패로 판정된다.
- 주문 받기 상호작용은 포함하지 않는다.

### 후속 이슈 후보

- `[Feat] 카운터 손님 주문과 전달 흐름 구현`

## 5. 하루 제한 시간과 판매 정산

### 목표

제한 시간 안에 주문을 처리하고, 처리 결과에 따라 하루 수익이 정리되는 구조를 만든다.

### 완료 기준

- 하루 제한 시간이 존재한다.
- 제한 시간 동안 손님 주문이 반복해서 발생한다.
- 주문 일치 여부가 보상에 반영된다.
- 전달 속도가 간단한 보너스로 반영된다.
- 제조 정확도가 간단한 보너스로 반영된다.
- 제한 시간이 끝나면 하루 수익이 요약된다.
- 손님별 개인 선호, 복잡한 품질 등급, 상세 평가표는 포함하지 않는다.

### 후속 이슈 후보

- `[Feat] 하루 제한 시간과 판매 정산 구현`

## 6. 첫 playable 설비 업그레이드

### 목표

하루 종료 후 번 돈으로 작은 설비 업그레이드를 선택하고, 다음 날 플레이에 변화가 생기게 한다.

### 완료 기준

- 하루 종료 후 업그레이드 선택 단계가 열린다.
- 제조 속도 개선 업그레이드 1개가 존재한다.
- 동선 개선 업그레이드 1개가 존재한다.
- 선택한 업그레이드가 다음 날 플레이에 반영된다.
- 복잡한 성장 트리나 넓은 가게 확장은 포함하지 않는다.

### 후속 이슈 후보

- `[Feat] 첫 playable 설비 업그레이드 구현`

## 7. 첫 playable 통합 점검과 임시 캐릭터 모델 적용

### 목표

캡슐 캐릭터와 그레이박스 기반으로 연결된 첫 playable 루프를 통합 점검하고, 임시 캐릭터 3D 모델을 적용해 이동감과 화면 가독성을 다시 확인한다.

임시 캐릭터 모델은 최종 아트가 아니다. 첫 playable에서 실제 캐릭터에 가까운 크기감, 회전감, 실루엣 가독성을 확인하기 위한 placeholder다.

### 완료 기준

- 하루 시작부터 주문 처리, 제작, 전달, 정산, 업그레이드까지 한 흐름으로 이어진다.
- 캡슐 캐릭터 대신 임시 캐릭터 3D 모델을 적용해 이동감을 다시 확인한다.
- 캐릭터 크기, 이동 속도, 회전 속도, 설비 앞 정지 위치를 재확인한다.
- 고정 쿼터뷰 카메라에서 캐릭터와 설비가 읽히는지 확인한다.
- 최종 캐릭터 아트, 최종 작업실 아트, 최종 애니메이션 품질은 포함하지 않는다.

### 후속 이슈 후보

- `[Feat] 첫 playable 통합 점검과 임시 캐릭터 모델 적용`

## 첫 playable 완료 정의

첫 playable은 다음 상태를 만족하면 완료로 본다.

- 플레이어가 작은 작업실 안에서 에일라를 직접 움직일 수 있다.
- 고정 쿼터뷰 카메라에서 작업실 동선, 카운터, 주요 설비 위치가 읽힌다.
- 플레이어가 한 번에 하나만 들고 제작 도구를 순서대로 오갈 수 있다.
- 손님 주문이 자동 등록되고, 플레이어가 포션을 만들어 카운터에 전달할 수 있다.
- 제한 시간 안에 주문을 처리하고, 주문 일치, 전달 속도, 간단한 제조 정확도에 따라 수익이 정리된다.
- 하루 종료 후 작은 설비 업그레이드를 선택하고 다음 날 변화가 반영된다.
- 임시 캐릭터 3D 모델로 이동감과 화면 가독성을 재확인한다.
- 최종 아트, 복잡한 품질 평가, 손님별 개인 선호, 마을 이동, 야외 탐험, 전투, 본편 서사는 포함하지 않는다.

## 구현 전 최소 Unity 확인 항목

구현 이슈를 만들기 전에 다음 항목을 확인한다.

- Unity version은 6000.3.x LTS를 유지한다.
- PR base는 `develop`으로 둔다.
- 첫 구현은 캡슐 캐릭터와 그레이박스 작업실로 시작한다.
- 임시 캐릭터 3D 모델은 첫 playable 통합 점검 단계에서 적용한다.
- 외부 에셋을 사용할 경우 라이선스, Unity 6000.3.x 호환성, 렌더 파이프라인 호환성을 확인한다.
- `Library/`, `Temp/`, `Obj/`, `Logs/`, `Builds/`, `UserSettings/`는 편집하지 않는다.
- `.unity`, `.prefab`, `.asset`, `.mat`, `.anim`, `.controller` 직접 YAML 편집은 피한다.

## 이번 작업 제외 범위

이번 문서는 구현 순서와 마일스톤을 정리하는 문서다. 다음 작업은 포함하지 않는다.

- Unity C# 구현
- Unity scene, prefab, material, animation, controller 직접 수정
- 외부 3D 에셋 다운로드 또는 프로젝트 반영
- 최종 아트 방향 확정
- 후속 구현 이슈 실제 생성
